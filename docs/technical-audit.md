## Highest-priority corrections

1. **IIoT page and diagram conflict with implementation.** Direct code shows local synthetic generation → feature selection → Isolation Forest prediction → MQTT alert publishing. It does not show MQTT subscriber inference, Plotly dashboard, normalization, payload rejection, or measured latency. `detect_anomalies.py` uses Matplotlib. `simulate_sensor_data.py` creates 1,000 rows, while `ai_agent.py` streams 50 readings at one-second intervals. README says 5,000+ samples and <300 ms; these can only be explicitly author-reported, not verified metrics. Prefer omit from hero.
2. **All diagrams are explanatory reconstructions, not measurement evidence.** Keep separate from hero and label accordingly. SO-101 diagram is a planned workflow, not completed implementation. Correct IIoT flow as above.
3. **Do not claim independent validation of every project.** Replace boilerplate “verified implementation details” with “Implementation notes and available project sources.” Missing public source is acceptable and should read “Academic project; public code not available.”
4. **No production deployment inference.** Industrial inspection is simulation; telemetry is a prototype with in-memory users; incident intelligence has documented tests, not proof of all passing in this session.
5. **Do not import weak README metrics into the redesign.** Telepresence mapping accuracy/collision reduction, UGV absolute GPS accuracy, Face Recognition accuracy/spoof claims require defined protocol and raw evidence.
6. **Preserve domain distinctions.** Embedded state-estimation project contribution is OS/deployment engineering, not authorship of power-system estimator. Robocon/hackathon are team work. J&J is Forage simulation, not employment. Nav2 planning experiments RRT/BiRRT/PRM should not be implied to be deployed Nav2 plugins.
